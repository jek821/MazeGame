PICO-8 · Design Document

Dynamic Map System

Screen-Space Component Rendering · Tile Lookup via Map Position

Overview

Rather than hand-placing every corridor and junction on the tilemap, the game assembles its layout at runtime from reusable components — hallway pieces designed once in the map editor and wired together in code. The camera locks to whichever component the player is currently inside. A hard-cut transition fires the moment they cross a boundary edge.

This system coexists with the existing portal system. Portals handle instant long-distance travel between named rooms. Components handle physical traversal through corridors and connected areas.

Minimum component width: 128px (16 tiles). This guarantees the screen is always fully covered so the hard-cut transition never reveals black edges.

Two Coordinate Spaces

Each component occupies a position in the map editor (where its tiles live) and a position on screen (where those tiles get drawn). These are independent — moving a component in the map editor has no effect on where it appears in the game.

A component stores both positions as flat fields: map_col / map_row for its tilemap location, and draw_x / draw_y for where it is rendered on screen. These match the argument order of PICO-8's map() call directly.

Component Data

Each component is a table. These are the fields every component needs:

map_col
Tile column in the map editor where this component's tiles begin — the horizontal source position passed to map(). — tile index
map_row
Tile row in the map editor where this component's tiles begin — the vertical source position passed to map(). — tile index
draw_x
Pixel column on screen where the component is drawn. For a component that fills the full screen width this is always 0. — pixels
draw_y
Pixel row on screen where the component is drawn. For a component that fills the full screen height this is 0. See the centering note below for shorter components. — pixels
pixel_w
Component width in pixels. Minimum 128. — pixels
pixel_h
Component height in pixels. Can be less than 128 for thin hallways. — pixels
exits
Table with up to four keys — left, right, up, down — each holding a reference to the adjacent component, or nil for a sealed wall. — table
Centering a short component vertically: set draw_y = flr((128 - pixel_h) / 2) when you define it. This is a one-time setup calculation, not something computed at runtime. draw_x follows the same logic horizontally, but full-width components always have draw_x = 0.

Coordinate Conversion — Screen → Tile

When checking whether a tile is solid, the player's screen position must be converted to the corresponding tile in the map editor. The player lives in screen space; the collision data lives in the tilemap. These two steps bridge them.

Step 1 removes the draw offset to get the player's position relative to the component's top-left corner. Step 2 divides by tile size and offsets by the component's tilemap position to get the actual tile.

local_x = screen_x - comp.draw_x
player x relative to component top-left
local_y = screen_y - comp.draw_y
player y relative to component top-left
tile_x = comp.map_col + flr(local_x / 8)
convert pixels → tiles, offset into tilemap
tile_y = comp.map_row + flr(local_y / 8)
same, vertical
fget(mget(tile_x, tile_y), solid_flag)
query the real tile in the map editor
is_solid() must be updated. It currently reads raw tilemap coordinates. Under screen-space rendering those coordinates are meaningless — it must go through this conversion using the active component's fields. Pass the component explicitly or read from Game.current_component.

Transition Logic

A transition fires the moment the player crosses a component's boundary. Because all components share consistent sizing, the perpendicular axis carries over directly — no remapping needed.

1
Detect boundary crossing

Check whether the player's screen position has passed the component edge in a given direction. Only check directions where exits[dir] is not nil — sealed sides are physically blocked by wall tiles and can never be reached.

2
Switch active component

Set Game.current_component to the exit's target. The new component's fields immediately apply to all subsequent rendering and tile lookups.

3
Reset the crossing axis

Place the player just inside the entry edge of the new component — one tile's worth of margin from the wall. The perpendicular axis carries over unchanged: a horizontal crossing preserves Y, a vertical crossing preserves X.

No exit = no code needed. If exits[dir] is nil the wall tiles handle it — the player is physically stopped. The boundary check is skipped entirely for sealed sides.

Rendering Pipeline

The camera is not used. All draw positions are raw screen coordinates. The map is drawn by specifying which tiles to copy from the map editor and where on screen to place them — this maps directly to PICO-8's map(map_col, map_row, draw_x, draw_y, tile_w, tile_h).

1
Reset camera

Call camera() with no arguments at the start of every draw. This clears any offset so all subsequent calls are in raw screen coordinates.

2
Draw component tiles

Call map(comp.map_col, comp.map_row, comp.draw_x, comp.draw_y, tile_w, tile_h). Only this component's tiles are drawn — nothing else on the tilemap is touched.

3
Draw entities

The player and all entities are positioned in screen space. Draw sprites directly at their x, y screen coordinates — no conversion or offset needed for rendering.

Scrolling (components wider or taller than 128px): calculate a scroll offset from the player's position, clamped between 0 and pixel_w - 128. Add the scroll to map_col (shift the tile source) and subtract it from all entity screen positions. For components exactly 128px wide the scroll is always 0 and no adjustment is needed.

Integration With Existing System

The component system is additive. Existing files and logic are unchanged except for is_solid().

Portal system — unchanged
  • Instant travel between named rooms
  • No physical traversal or mapping needed
  • Triggered by proximity
  • Stays in rooms.lua
Component system — new
  • Physical traversal through corridors
  • Edge-triggered hard-cut transitions
  • Camera locked per component
  • Defined in new components.lua
is_solid() must be updated. It is the only existing function that breaks under screen-space rendering. It currently uses raw screen coordinates as tilemap coordinates — that assumption is no longer valid. It needs the two-step conversion above (strip draw offset, divide by 8 and add map position), reading from Game.current_component.
