Maze Game Audit — May 21st, 2026
=================================

Player State Table
------------------
- ammo — still in Player state but not integrated into shooter logic.

randomItemSpawnInRoom()
-----------------------
- Needs a better name.
- Does not need if itemId == branching — spawn logic is the same for all item types.
- Should have a table associating item names (e.g. "coin", "ammo") to asset/sprite IDs instead.

renderRoomItems()
-----------------
- Remove the room parameter; get current room from game state instead.

detectItemOnPlayer()
--------------------
- All logic should be abstracted into a generic collision check function that takes two objects and checks for overlap.
- Each frame, call this function passing in the player and every object it could collide with (coins, ammo, zombies, etc.).
- This would allow cleanly abstracting out pickup logic and damage-taking as separate handlers.

handle_keys()
-------------
- Looks complex but is not fundamentally bad.
- Potential optimization: maintain a table of only the valid/used key codes and iterate over those instead of checking all 256 keys every frame.

is_solid()
----------
- Looks good. tile_x/tile_y naming fix applied. flags table implemented.

_init()
-------
- Spawning items in the room should be moved into a dedicated enter_room() or load_room() function
  to be more reusable across rooms.

_update60()
-----------
- State changes like shoot_cooldown decrement and pellet life/deletion should live in an
  updateGunState() function (or better-named equivalent).
- Timer/HUD state changes should similarly move to an updateHudState() function.

renderTopHud()
--------------
- Make HUD cleaner by moving to a dedicated state table.
- Create a top_hud table with element values and their screen positions, then iterate over it to render.

_draw()
-------
- Need more dedicated render functions to hold drawing logic — _draw() should only orchestrate
  calls, not contain inline drawing code.
